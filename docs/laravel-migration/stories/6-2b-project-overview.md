# Story 6.2b: Project Overview

**Status:** review · **DoD variant:** Conversion · **Epic:** 6 · **Covers:** C-03, FR24, FR58, UX §2.5 · **Gate:** `@client&@ui` (see Deviations) · **After:** 6.2a, 1.8b, 1.8c, 3.4. Test mode only.

## Story
As a signed-in client, I open my project and see whose turn it is, what to do next, how far along it is and what allowance is left.

## Acceptance criteria
1. `GET /project/{id}` (sign-in required; signed-out redirects). Non-member, unknown or malformed id answers 404. The first paint carries the snapshot (same shape as `GET /api/projects/{id}`).
2. Turn banner per status with the one primary action: AWAITING_BRIEF "Start your brief", CONCEPTS_READY "Review concepts", FINAL_FILES_READY "Download ZIP", ON_HOLD "Check messages"; the other states show no button. Copy and turn come from `lib/status.ts`.
3. Stage tracker from `snapshot.timeline`; allowances for concepts and revisions as used / in progress / left (`AllowanceMeter`); recent activity (last five system messages); shortcuts to brief and files.
4. Polls `GET /api/projects/{id}` every 10 s (`usePolling`, `POLL_INTERVALS.customerProject`); a status change is announced politely. The page holds no images, so a poll downloads none.

## Behaviour notes
`@client&@ui` selects nothing: no spec carries that pair of tags. The owner decided `@upsell&@ui` stands in for it, so the parity page objects (`tests/parity/pages/laravel/project-ui.ts`) serve the Overview, 6.3 and 6.4.
